## БЛОКЕРЫ перед e2e (ломают сам выход видео)

1. **TTS-конкатенация рушит озвучку.** Чанки склеиваются через `amix` с накапливающимся `adelay` → на видео >5000 символов (любое реальное 19-22k = 4-5 чанков) голос накладывается сам на себя / обрезается. Чинить: конкатенация через `concat` (а не amix), паузы вставкой тишины, не adelay. [tts.py]
2. **FLUX-фолбэк не работает** (queue.fal.run требует поллинга) — сцена без стока = дырка. РЕШЕНИЕ КЛИЕНТА: НЕ оживлять FLUX (он врёт в тексте/лицах/числах). Заменить фолбэк на: реальные фото (Wikimedia/Wikipedia/Internet Archive) + text-overlay; data-сцены → Remotion-инфографика; FLUX только крайний случай и только простое/абстрактное (без текста/лиц/чисел). [image_gen.py, +новый photo-источник]
3. **Скачанные mp4 не валидируются** (нет проверки content-type/размера/декодируемости) → битый файл ломает сборку. Чинить: ffprobe-проверка после загрузки, иначе считать сцену неудачной. [stock/multi.py, clips.py]
4. **FCPXML src не XML-экранируется и не URL-кодируется** → спецсимвол в пути/имени ломает проект DaVinci. Чинить: escape + quote пути ассета. [fcpxml_export.py]
5. **save_checkpoint() затирает metadata/delivery/created_at/style/music_mood** при каждом вызове → API теряет титулы/ссылку/прогресс. Чинить: мерджить, а не перезаписывать checkpoint. [orchestrator.py]
6. **call_llm может вернуть None** → `len(script)` и парсинг далее падают. Чинить: пустой/None ответ = ошибка с ретраем/фолбэк-моделью. [utils/llm.py]
7. **Темп нарезки сломан:** 1 сток-клип на всю сцену (30-90с статики) вместо документального монтажа ~6с. Самое заметное «дёшево» в кадре. Чинить: shot-splitting (см. визуальный апгрейд). [clips.py/assembly.py]

## Надёжность (доделать до массовых прогонов)

- Частичное аудио при падении одного TTS-чанка — весь прогон валится, готовые чанки теряются → ретрай чанка / фолбэк на Edge поштучно.
- Неатомарная запись checkpoint.json → reader ловит битый JSON; WebSocket навсегда обрывает прогресс при единичной ошибке чтения. Чинить: запись через temp+rename; WS — не падать на одной ошибке.
- Отмена задачи не прерывает реальную работу; `_running_tasks` теряется при рестарте (утечка/потеря задач).
- source_context из транскриптов раздувает промпт без лимита → 400/таймаут. Лимитировать.
- GDrive-аплоад читает весь zip (~480MB) в память → OOM убивает пайплайн в самом конце; при успехе zip удаляется → кнопка скачивания исчезает. Стримить и/или не удалять.
- Дрейф таймлайна fcpxml: offset на spine ≠ сумма длительностей; spine-длительность может превысить медиа → Media Offline; scene_duration<=0 → ffmpeg ломается.
- apply_ken_burns: синхронный subprocess.run в async → блок event-loop.
- generate_metadata без fallback-модели — падает при сбое primary. scene_tagging на экспериментальной grok-build-0.1.
